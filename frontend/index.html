WHAT EACH NOTEBOOK DOES

Research method summaries

01
Claim-level support scoring

For each claim, the notebook retrieves the top three evidence passages. It combines entailment, similarity, and contradiction as: support = 0.5 × entailment + 0.3 × similarity − 0.7 × contradiction. The answer hallucination score is the mean of 1 − support across claims.

02
Binary answer classification

Loads pminervini/HaluEval QA data, expands each record into a right-answer example (0) and hallucinated-answer example (1), uses an 80/20 split with random state 42, and evaluates a balanced Logistic Regression pipeline.

03
Knowledge-aware LLM judging

Compares Yes/No next-token probabilities with and without knowledge; evaluates AUROC, accuracy, precision, recall, and F1. It also generates closed-book answers and uses token recall and repeated-sample consistency as signals.

i
Notebook execution

The notebooks are included unchanged as source artifacts. Their Python dependencies and pretrained models are not executed by this static site. Open them in Jupyter or Google Colab to run the original experiments.

EXPERIENCE RETRIEVAL

Experience-MCF branch

Checks whether the question is an outlier. If it is not, the repository retrieves up to three semantically similar validated examples from GSM8K training experiences. The retrieved examples are added to the three normal-agent prompts.

The uploaded README notes that experience retrieval did not return examples for every evaluated question.

METHODS & INTERPRETATION

Detection Methods

Three notebook methods and the MCF pipeline approach hallucination from different angles: evidence support, supervised classification, model judging, and collaborative answer selection.

A / 01

Evidence retrieval + NLI

Retrieve supporting passages for individual answer claims, then classify the relationship between evidence and claim.

support = 0.5E + 0.3S − 0.7C
hallucination = 1 − support
E entailment · S similarity · C contradiction
B / 02

TF–IDF classifier

Represent knowledge, question, and answer text with unigram/bigram TF–IDF features. Train a class-balanced Logistic Regression classifier.

max_features = 50,000
ngram_range = (1, 2)
max_iter = 1,000
HaluEval QA · 80/20 split · random_state 42
C / 03

LLM judge + consistency

Compare the model’s Yes/No judgement probabilities with and without knowledge, then examine generated-answer overlap and repeatability.

inconsistency = 1 − consistency
score with AUROC / F1
Qwen2.5-1.5B-Instruct · temperature 1.0 · top_p 0.95
D / 04

Multi-agent collaborative filtering

Use an adversarial challenge response as a comparison signal, but rely on answer validity, consensus, and arithmetic trace checks for final selection.

combined = 0.5 × embedding
+ 0.5 × AMR Smatch F1
Llama 3.2 3B · Nomic Embed Text · GSM8K
IMPROVED SELECTOR PRIORITY

Selection rules from improved_mcf_selector.py

  1. Verified consensus: an answer supported by at least two valid agents and at least one verified arithmetic trace.
  2. Valid consensus: another valid answer supported by at least two agents.
  3. Single verified answer: if no consensus exists, choose a mathematically verified valid candidate.
  4. Fallback: choose the valid candidate with the lowest original combined AMR/embedding score.
  5. No valid answers: return no prediction.

The arithmetic trace checker is lightweight, not a complete proof system. Natural-language equation formatting may affect whether a trace can be parsed.
